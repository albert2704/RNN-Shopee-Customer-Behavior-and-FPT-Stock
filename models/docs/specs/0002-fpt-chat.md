# FPT evidence chatbot

**Date:** 2026-10-07 · **Status:** Accepted from the chat request and API-service choice.

The user expects a visible conversation for ordinary stock customers, backed by the FPT daily workflow, Neo4j and RAG. “Tôi có 200 triệu, nên đầu tư như thế nào?” should receive a useful plain-Vietnamese answer grounded in the dated FPT forecast, with at most one relevant clarification. The RNN works behind the scenes; mentioning a budget does not request a calculator or a technical lesson. This extends 0001; it does not alter either classroom experiment or train a language model.

## Decisions
- Use OpenAI Responses with a configurable model and server-only key in ignored `models/.env`. Default `gpt-4.1-mini`; read settings on requests so adding a key needs no restart. Never expose secrets in status, browser, logs, source ZIP or Git.
- Neo4j Community in a dedicated Docker container, loopback ports, generated local password and named data volume. Do not install a local language model.
- Build a small versioned corpus from the canonical daily forecast, source provenance, model configuration, test metrics, and educational scope. Actual Neo4j fulltext retrieval (normalized Vietnamese) plus graph traversal supplies context before API generation. Parameterized fixed Cypher only; no LLM-generated database commands. This is lexical RAG, not vector similarity search.
- Keep evidence graph snapshots distinct by payload hash. Every answer carries validated citation IDs, source excerpts or deterministic summaries with source pointers, input cutoff and graph trace. No silent fake AI response if the API key or database is unavailable.
- `reply_mode(messages)` gates technical and calculation behavior. Calculate with Decimal outside the LLM only for an explicit request such as a share-count question. A budget mention alone does not trigger calculation. Distinguish investable capital from reserves, prices and tolerable losses; ask for clarification if ambiguous. Fees, taxes, slippage and order-lot feasibility are not modeled. Do not generate automatic 10%/20% stress scenarios.
- The assistant covers FPT evidence only. Explain the forecast, dated saved price and next-recorded-session meaning in plain Vietnamese by default. Ask one relevant clarification at a time and retain known horizon, reserves and risk preferences. Give practical answers without inventing stock rankings, company fundamentals, guaranteed returns or long-term projections from one-step output.
- `prepare_evidence(evidence, data, technical=...)` summarizes retrieved documents and graph facts before generation in default mode. Retain exact metrics when a user explicitly asks about model performance or other technical details. Do not automatically show MAE, baseline comparisons, budget/cash tables or stress tables. Sources and graph trace are secondary, collapsed references. Follow-up buttons are questions that the assistant can answer, rather than questions asking it to know the user's personal preferences.
- Chat is available at `#chat`, from the demo header and a prominent link on the FPT daily view. Conversations stay in React memory; submitted recent messages/evidence are sent to OpenAI with `store=False`. No server chat-history store. Existing replay pauses when navigating away.

## Acceptance
1. Visible Vietnamese chat for ordinary stock customers, practical suggested prompts, multi-turn messages, pending/error/retry states, collapsed evidence references and working navigation.
2. Local setup and key status are accurate; missing credentials never produce canned investment advice as though generated by an LLM.
3. Live Neo4j import, normalized retrieval and graph facts agree with the current canonical daily payload, including after a refresh. Baseline and data dates are always retrieved.
4. A budget mention alone does not calculate. Explicit share-count requests use exact Decimal arithmetic; unknown/ambiguous amounts, retrieval injection, origin/body/rate/concurrency boundaries and API-provider errors are handled.
5. Existing replay logic and TypeScript build pass. Package includes chat source, setup example and docs, excluding secrets/database/runtime. Real model generation is verified only after a key is configured; otherwise explicitly report that limitation.
6. After the customer-facing correction, live acceptance must confirm: the 200-million prompt receives a direct plain-language FPT answer without automatic MAE/calculation/stress content; a follow-up stating horizon and reserves is remembered; unsupported stock comparisons do not invent facts; an explicit share-count question calculates correctly; technical questions retain accurate metrics. Each reply asks at most one relevant clarification, and the dated one-session estimate never becomes a confidence claim or long-term forecast.
